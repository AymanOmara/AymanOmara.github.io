CASE STUDY · .NET 8 API + FLUTTER CLIENT

An e-commerce app that reminds you to reorder.

Rahtk is a shopping app with one extra idea: group the products you buy regularly into a reminder, and the app nudges you when it’s time to order again. I built both sides: a layered .NET 8 API with background jobs and push notifications, and the Flutter client that uses it.

The API, in Swagger

Swagger documents every endpoint. I configured it to send the JWT bearer token and an Accept-Language header with each request, so every call can be tried from the browser in either language.

Swagger UI recreated from the controllers, models and resource files in the repository. The data in the examples is invented.

The idea

Many household purchases repeat on a rhythm: coffee every month, filters every few weeks. Rahtk lets a shopper pick several products, give the group a title and an interval in days, and get a push notification when it’s time to reorder, alongside the usual browsing, favourites, cart and checkout.

The API

  • A .NET 8 solution split into Api, Application, Domain, Contracts, Infrastructure, Shared and an IoC composition root.
  • 32 endpoints across users, products, categories, orders, addresses, payment options and reminders, with ASP.NET Core Identity, JWT access and refresh tokens, and Swagger.
  • EF Core on SQL Server with 11 entities. Product names and descriptions are stored in both languages, and responses are localized from the request’s language.
  • Each reminder is a Hangfire recurring job stored in SQL Server. When it’s due, Firebase Admin sends the push and the API saves it to the user’s notification centre.

One request, end to end

Controllers stay thin. They read the user from the JWT claims and hand off to an application service. The service works through a unit of work over EF Core, maps entities to DTOs, and wraps the result in one BaseResponse<T> envelope with a localized message. The status code travels inside that envelope.

Rahtk.Api/Controllers/ReminderController.cscontroller
[Authorize]
[Route("api/[controller]")]
public class ReminderController : ControllerBase
{
    [HttpPost("add-reminder")]
    public async Task<IActionResult> AddReminder([FromBody] AddReminderModel model)
    {
        var email = User.FindFirstValue(ClaimTypes.NameIdentifier);
        var result = await _reminderService.AddReminder(model, email ?? "");
        return result.ToResult();
    }
}
Rahtk.Application/Features/Reminder/Service/ReminderService.csservice
public async Task<BaseResponse<ReadReminderModel>> AddReminder(
    AddReminderModel reminderModel, string email)
{
    var result = await _unitofWork.Reminder.AddReminder(reminderModel.ToEntity(), email);
    return new BaseResponse<ReadReminderModel>
    {
        data = result.ToModel(),
        statusCode = 200,
        success = true,
        message = _languageService.Getkey("reminder_added_successfully").Value
    };
}
Rahtk.Api/Utils/ToResponseResult.csenvelope → HTTP
public static IActionResult ToResult<T>(this BaseResponse<T> response)
{
    return new ObjectResult(response)
    {
        StatusCode = response.statusCode
    };
}

Data model

11 entities in EF Core on SQL Server, built up over 31 migrations. Products and categories store their names and descriptions in both languages, and the API returns the right one for the request. Deletes are soft, so a product that’s gone from the catalogue still shows up in past orders. Two join tables model the many-to-many links: favourites and reminder products.

Reminders, end to end

The reminder feature crosses every layer: the HTTP API, the database, a background job server and a push provider. Update replaces the job under the same id, and delete removes it.

  1. CreateThe app posts a title, products and an interval to add-reminder.
  2. PersistEF Core saves the reminder and its product links in one unit of work.
  3. ScheduleA Hangfire recurring job is registered under the reminder’s id and stored in SQL Server.
  4. FireWhen the reminder is due, the job builds the message.
  5. PushFirebase Admin sends it to the device’s FCM token.
  6. RecordThe API saves a notification row for the in-app notification centre.

The mobile app

  • 20 screens: onboarding, sign-up with email OTP verification and password reset, home, categories, product details, favourites, cart, checkout, order history, addresses with location lookup, reminders and a notification centre.
  • One Cubit per screen on separate common, domain, data and di packages, with get_it for wiring.
  • A Dio client that returns a typed Result, and a refresh-token interceptor that holds failed requests during a 401, refreshes the session once, then retries them.
  • Firebase Cloud Messaging for pushes, shown in the foreground with local notifications, in Arabic and English.
