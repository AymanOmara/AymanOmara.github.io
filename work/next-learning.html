CASE STUDY · CLIENT PROJECT · FLUTTER

A course platform app, built solo from Figma.

Next Learning is a mobile client for a training platform: learners find courses by their interests, filter them in depth, and send inquiries. I built the whole app alone, from a Figma design against the client’s existing API, in Arabic and English.

85Commits, all mine
40API endpoints
22Screens

The brief

Turn a Figma design into a working app on top of an API that already existed: browsing and searching courses, course details, and a way for learners to reach the provider, with guest browsing and sign-in only where it matters.

What I built

  • Onboarding: sign-in or continue as a guest, two-step registration with a profile photo, then a four-step interests flow from main category down to topic.
  • Discovery: a home tab with a hero carousel, courses by category, strategic providers and FAQs, and an Explore tab with paginated search.
  • A 10-filter search drawer whose category filters cascade (main category, category, sub-category, topic), plus a date range.
  • Course details in six tabs, from the outline to the time plan, with a course inquiry sheet and prices for signed-in learners.
  • Requests with Inbox and History tabs, profile editing, change password, contact us, and a language switch.

Engineering

  • Strict package boundaries: the app talks to domain only and never imports data. get_it wires the layers, with registerFactoryParam to pass arguments into screen cubits.
  • Every call goes through one API caller that returns a sealed Result. On a 401, a refresh-token interceptor refreshes once, queues and retries the other requests, and marks retries so they can’t loop.
  • A generic pagination controller that drops stale responses when a new search starts.
  • The filter drawer and the Explore screen never reference each other: the drawer publishes a search on an event bus and Explore reloads. The same bus refreshes Requests and Interests after changes elsewhere.
  • One Cubit per screen with LoadingState fields, shimmer placeholders, named routes and theme tokens.
